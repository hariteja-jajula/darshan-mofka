Darshan → Mofka Streaming Overhead

Workloads (1 of 2)

Each workload drives the Mofka connector at a different I/O burst rate. Scale knobs come from workloads/workload.config; topology fixed at 2 nodes, 1 app task + 1 broker, memory partition, ofi+tcp.

c — tight-loop POSIX/STDIO microbenchmark
env that matters: events→EPOCHS (250k), checkpoints→CHECKPOINT_EVERY
Opens train.log and does EPOCHS × 64-byte write() back-to-back (one Mofka push each), plus an STDIO checkpoint every CHECKPOINT_EVERY epochs. No compute between I/O → highest burst rate of the four.
python-ml — shard read + train + checkpoint
env that matters: events→ML_EPOCHS (90k), checkpoints→ML_CHECKPOINTS, ML_FILES=6 shards
Writes 6 binary shards + manifest, then each epoch reads every shard back and reduces it (torch/numpy), checkpointing on cadence. Real compute interleaves I/O → pushes spread out in time.

Workloads (2 of 2)

mpi — collective MPI-IO with fsync
env that matters: events→STEPS (500k), tasks→MPI ranks
Opens a shared file, then STEPS × [MPI_File_write_at_all + MPI_File_sync + barrier + MPI_File_read_at_all] at disjoint per-rank offsets, then closes. fsync-bound collective I/O → high per-push latency.
dlio — AI-framework dataset staging (DLIO Benchmark)
env that matters: events→num_files_train (90k), record_length=4096, num_samples_per_file=4, format=npz, generate_data=True
Runs DLIO's data-generation stage: writes num_files_train NPZ dataset files via TF/numpy (real POSIX writes), no training loop. Models the dataset-staging I/O phase of an AI pipeline.
All numbers on the following slides: moderate campaign, 3–5 reps/arm, warm-up run discarded, 2node / 1task / 1broker-separate, 1 memory partition, 16 rpc threads. Fidelity verified by per-rank pydarshan integer-counter compare (native vs streamed).

Headline. The Darshan runtime alone adds near-zero cost (+0.5…+2.3%). Streaming overhead is set by I/O burst rate vs drain throughput: compute-interleaved workloads (python-ml +14%, dlio +6%) stream losslessly for free in best-effort mode. Tight-burst workloads face the tradeoff — best-effort is cheap but lossy (c drop +26% / 64% shed), block is lossless but costs more (c block +53%, mpi +126%). Fidelity is EXACT whenever events are delivered.
